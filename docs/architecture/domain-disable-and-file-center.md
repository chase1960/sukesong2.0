# 域级真实启停与文件中心边界

> 状态：DESIGN（文件中心仍待实施；域运行单元重构已在本地完成，见下方执行计划，未部署公网）。2026-09-21。
> 基于 fast `6570ca9` 静态审查。本文不自动覆盖 public_api 1.x 和财务既有存量续办契约；变更需独立 CORE-CANDIDATE、兼容处理及回归。

## 1. 目标及准确含义

2026-09-21 用户纠正后，实施主线改为**域级数据访问与执行单元的统一生命周期**，不是给业务函数散补守卫。具体获授权切片、兼容方式与完成标准见[运行单元 CORE-CANDIDATE](../plans/2026-09-21-domain-runtime-CORE-CANDIDATE.md)。下文审查保留为改造前事实。

用户要求：停用文件中心后，其业务查询、写入和后台执行真正停止；其他域无关附件功能照常使用。跨域仅通过受控公共接口，不靠隐藏页面或开发者自觉。

不是独立服务器/数据库要求，也不是清空表、断开全站数据库或卸载 Python 模块。完全停用指**停用成功后不再进入该域业务 handler 或产生该域业务读写**；内核读取启停状态、权限、依赖和审计，以及恢复操作仍须可用。静态注册声明可以读取，但不得携带业务查询、启动任务或外部副作用。

## 2. 文件能力分层与数据归属

| 层 | 所有权和责任 | 停用文件中心时 |
|---|---|---|
| 平台基础附件能力 | 文件内容存取、稳定附件/版本引用、来源所有权、受控下载、保留引用；复用统一身份和授权 | 保持服务，不因中心状态改变授权 |
| 可选文件中心域 | 企业目录、中心文件索引、共享管理、展示版本历史、回收站、内容解析及 AI 检索 | 所有业务入口与后台任务停止，数据保留 |
| 邮件、任务、财务、行业域 | 自己的业务数据、附件关系、访问权限、发送快照 | 无关功能继续，经公共附件契约访问既有附件 |
| 文件中心应用 | 员工工作页面 | 入口收起，旧链接明确停用，不能绕过服务端 |

这是目标划分，不代表当前已有完整统一附件 API。优先适配已有存储而非复制一套；现有兼容附件不在本轮文档阶段搬迁。文件中心自己的目录与版本业务元数据归中心，基础层只保留其他域独立读取既有附件所需的稳定内容引用与授权事实，不把整套中心搬进 core。

文件可独立上传，不要求案件或行业分类。其他域引用 file/version ID，不使用存储路径或直接读中心表。无关附件的访问不得依赖中心目录查询或中心提供的权限回调；确实依赖中心共享能力的资源不属于“无关”，停用前必须列为依赖或明确拒绝访问，不能为保可用放宽权限。禁止复制第二套 ACL 来假装解耦。

“所有文件都存”是统一收纳各种格式，不代表不设大小/安全限制。预览与 AI 解析可失败，内容保存和授权下载不依赖解析成功。中心停用后不允许改走基础附件口继续操作中心所属文件，这也是绕过停用；其他域访问只能基于自己已合法建立的附件关系。

## 3. 启停协议

### 3.1 启用、停止接单与完全停用不能混称

- 启用：正常读写、后台任务、检索及跨域接口。
- 停用请求：在服务端关停新业务准入，检查强依赖、已接收请求、队列和外部副作用。尚有工作时不得返回“已停用”。首版优先阻止停用并显示明确待处理项；需要排空时再引入最小可见过渡状态，不先造大型编排器。
- 完全停用：没有该域在执行的业务请求/任务；新接口拒绝、排队任务不会启动，重试/回调也不写入该域。保留数据与内核治理入口。
- 重新启用：校验依赖和协议，恢复原数据；队列重新核对身份、版本和幂等键，不能盲目补跑重复副作用。

已有财务“停用后继续存量审批/过账/付款”是旧语义，不能直接称完全停用。迁移选择应明确为“停止新业务但允许收尾”，或收尾完成后才能完全停用。不得直接禁止已运行流程、丢弃审批或重写历史实例版本。

### 3.2 执行边界

所有 HTTP、AI Tool、Action、Service、对象读写、后台 worker、定时任务与回调均经相同的域级准入规则。提交停用与业务进入须有并发协调，不能只在执行前读一次 enabled 后不再管。

短请求可复用既有生命周期锁和请求事务；长解析不能长期持有全局数据库锁。长任务必须可识别 owner、运行状态和停止策略，并在开始/持久化结果前检查有效执行资格。停用要等待或明确取消在途任务，不能宣称标志翻转就中断了进程。具体最小实现需 CORE-CANDIDATE 验证，不能为每个域复制队列。

外部发送/付款一旦开始可能不能撤销：先核实结果并安全收尾，无法确定则阻止完全停用；不得为了停用自动重发、付款或强杀共享进程。失败回调也不能成为停用后的业务写口。

## 4. 跨域公共接口

- 复用现有 public_api/Action/Service/Event；不新增按领域硬编码的一组公共 BFF 路由。
- 统一检查调用者身份、目标域启用状态、声明的依赖/资源、版本、权限与输入。依赖声明不等于授权。
- Action/Service 之外的对象读取、事件发布/消费和后台任务也应有明确的调用归属；不能因缺失调用上下文静默把行业代码当核心。
- 错误明确区分领域停用、权限不足、依赖不可用，不伪装空列表/成功；AI 同样不能绕过。
- 强依赖阻止目标域停用；可选集成失效仅禁用相关功能。API1.7/kernel0.3.0本地候选已支持manifest域级optional_dependencies，目标权限与执行屏障保留；仍不是能力级依赖求解或资源白名单，不把普通接口失败假装成集成成功。公网未部署。
- Python 同进程不是安全沙箱；公共入口约束和静态边界检查共同约束可信插件代码，不保证任意恶意插件无法访问数据库。

### 4.1 跨域写归属与收录动作（2026-09-21 讨论确认，随统一附件契约实施）

- 跨域写动作定义并执行在**写入方**：操作在谁的表里建立事实，动作就归谁的公共 Action；另一方不需要被调用、不感知目标域存在。反向同理——发带附件的消息是消息域动作，只引用附件 ID，不关心该文件是否被文件中心收录。用户发起的跨域操作（如从消息建任务）由前端编排两个域各自的公共动作完成，不要求两个域互相认识。
- 收录类动作一个动作服务所有来源：只有 `ingest(附件 ID, 目标位置)`，不按来源拆 `ingest_from_message/email` 之类接口；来源体现为参数或基础附件层既有授权事实，不是接口维度。收录建立目录索引条目并引用附件/版本 ID，不复制字节，按（附件 ID, 目标位置）幂等。
- 收录前的源访问权由基础附件层的授权事实裁决（见第 2 节），不要求源域在线、不复制第二套 ACL、不让源域当中间人；收录方另查自己的写入权限，两层检查互不放宽。源域停用或源记录删除后，已收录条目不失效；中心停用后源附件下载照常，两个方向对称。
- 前端与 AI 入口统一走动作目录：页面按“当前用户 + 已启用域 + 资源类型”从动作目录渲染可用动作，不逐页硬编码；域停用时动作从目录消失、入口自动收起，直达调用被服务端拒绝。AI 归档与手动点击执行同一动作，同确认、审计与幂等（AI Tool 是 Action 的受管投影，基线 5.7）。
- 本节为设计约定，不是已交付能力：落地时随阶段 3 统一基础附件契约一起版本化并补回归测试；实现前不得引用本节宣称接口已存在。

## 6. 实施顺序与验收门禁

1. 盘点附件现状与 ownership、依赖及运行入口，定最小公共附件契约；不迁移真实数据、不搬旧分支代码。
2. 独立 CORE-CANDIDATE 补启停语义和准入覆盖，明确财务兼容路径；版本化变更不能把文档直接当迁移。
3. 再实现可选文件中心域和页面；AI 索引/解析只属该域，不反向绑住基础附件。
4. 独立测试环境执行下表，再经授权在内部站验证；本轮设计审查不实际停用员工使用中的域。

| 场景 | 必须证明 |
|---|---|
| core + 协作，不装文件中心 | 原有附件上传、授权下载仍可用 |
| 中心启用后完全停用 | UI、直达 HTTP、AI、查询/写入/回调拒绝；域 handler 和业务表读写不发生 |
| 有运行中解析、队列、并发请求 | 停用被明确阻断或进入可见收尾；不能报告成功后仍有业务写入 |
| 中心停用后其他域使用附件 | 原有合法引用可下载，无关操作正常，权限不放宽；中心专属能力明确不可用 |
| 强依赖或未决外部副作用 | 阻止完全停用，列具体对象，不自动清数据或扩大权限 |
| 重新启用 | 文件、权限、版本、关联保持，任务不重复副作用 |
| 越权或未声明跨域访问 | 公共接口拒绝，静态检查拦截直接私有调用；包含对象读和事件路径 |

验证应使用 handler 探针、任务状态、业务表/文件校验与双账号页面操作，不以 enabled=false 或菜单消失代替“真实停止”。内核治理状态/审计读取不计为域业务执行。
