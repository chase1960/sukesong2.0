# 尚书企业平台、插件协议与产品信息架构（2026-08-31）

> **文档状态：ROADMAP（长期插件与多企业架构）**
> 本文为插件目标 spec；总体顺序见 [长期路线](../../长期路线.md)，完成度见 [当前进展](../../当前进展.md)。这里的目标 manifest 不替代现行 public API / workbench v1 机器契约。
>
> **状态：长期协议目标与当前过渡基准。** 尚书不再只是一组固定业务页面，而要成为工程师可为企业安装、配置和二次开发业务应用的平台。Frappe core 承担对象、权限、页面、流程和应用安装底座；尚书补齐统一产品壳、插件协议、AI 动作治理、流程中心和企业交付规范。完整 manifest loader、市场、签名和在线安装属于后续 P3；当前先实现内置可信领域的最小注册与安全启停，不伪装成完整插件平台。

## 1. 产品目标

1. 一套平台覆盖数据管理、流程设计、流程办理、消息、任务和 AI 协作。
2. 财务、文件、合同、项目等领域能力以插件/App 安装，不修改平台 core。
3. 同一插件能够声明对象、字段、页面、动作、流程、AI 工具、权限和迁移。
4. 本阶段仍按“一家企业一个独立部署”运行，但产品界面和协议预留企业切换、组织、应用授权与多企业数据边界。
5. 配置型扩展优先；可信代码插件其次；第三方任意代码必须独立进程或经过签名与安全审核。

## 2. 平台与插件边界

### 平台核心必须提供

- 身份、企业、组织、角色、权限与会话。
- 插件安装、依赖检查、启停、升级、迁移、健康检查与数据保留。
- 对象/字段元数据、通用数据视图、流程运行时、流程中心和实例时间线。
- 文件与附件基础服务、审计事件、通知、搜索和密钥管理。
- ActionDef / ToolDef、人工确认、幂等、超时、审计与按用户裁剪 AI 工具目录。
- 统一产品壳、导航插槽、页面插槽、设置插槽和前端设计令牌。

### 业务插件拥有

- 自己命名空间内的 DocType、页面、报表、Workflow、角色补充和初始化数据。
- 自己的领域动作、业务不变量、AI 工具投影和升级迁移。
- 自己的数据；跨插件只能调用公开服务/动作或订阅版本化事件，禁止直接更新他插件表。

财务插件必须在受控领域服务内保证金额精度、过账、append-only 和红冲，不能只依赖页面或工作流。文件插件负责文件夹、版本、标签、搜索和归档，但二进制存储、附件引用和访问控制属于平台文件服务，供所有插件复用。

### 当前过渡期：内置可选领域

在正式插件 loader 完成前，已随部署安装的可信 Frappe App 可以作为“内置可选领域”注册，但必须遵守与未来插件一致的边界：

1. 平台保存独立于“App 是否安装”的领域启用状态；停用不是卸载，不执行 schema 回滚或数据删除。
2. 领域声明自己的导航、数据集、流程模板、页面、动作、角色补充和 AI ToolDef；平台只聚合已启用领域的声明，不写死财务资源。
3. 停用后隐藏普通入口、禁止新建领域记录和新发起领域流程；已在运行的实例继续按其冻结版本办理，历史记录和审计可查。
4. 通用 AI 工具目录移除停用领域工具；为完成既有实例所需的动作，只能在该实例上下文、权限和确认策略内继续使用。
5. `shangshu_finance` 是第一个真实内置可选领域；不创建抽象“示例域”，也不为验证扩展机制另造合同/用印业务。

## 3. 尚书插件协议 1.0（目标形状）

每个插件必须带 manifest，至少包含：

```yaml
id: com.shangshu.finance
name: 尚书财务
version: 1.0.0
platform_api: ">=1.0 <2.0"
dependencies:
  - platform.workflow@">=1.0"
  - platform.files@">=1.0"
exports:
  doctypes: [finance.voucher, finance.account]
  actions: [finance.voucher.post, finance.voucher.reverse]
  workflows: [finance.expense_approval]
  pages: [finance.dashboard]
  tools: [finance.voucher.query]
permissions:
  - object: finance.voucher
    actions: [read, create, post]
migrations: [001_initial]
```

硬规则：

1. 插件 ID 永久不变，使用反向域名；对象、动作、工具、事件、路由、配置、队列、缓存键全部进入插件命名空间。
2. 重复注册默认安装失败，禁止“后加载覆盖前加载”；替换必须由原资源所有者和平台 allowlist 明确授权。
3. manifest 声明平台兼容版本、依赖、可选依赖、冲突、资源、权限、外部服务、迁移与卸载数据策略。
4. 安装顺序为预检 → 冲突扫描 → 权限确认 → 备份 → 迁移 → 健康检查 → 激活；卸载默认只停用并保留数据。
5. Frappe Python/Node TypeScript 进程内插件均视为全信任代码。未来开放市场前必须增加签名、SBOM/许可证扫描、代码审核和隔离执行。

### AI 工具投影

插件不得把任意 Python/JavaScript 函数直接暴露给 AI。每个工具必须声明唯一 ID、版本、输入/输出 schema、effect、角色、记录范围、确认策略、幂等键、超时、重试、审计和敏感字段。AI 看到的工具目录由“当前企业 + 已安装插件 + 当前用户权限 + 当前业务上下文”动态裁剪。

## 4. 历史入口设想（不再定义导航）

以下表保留 2026-08-31 的背景，不能据此增加“数据/流程设计”等普通用户一级入口。当前产品结构见根目录 [项目总览](../../项目总览.md)；具体动线由 [前端规范](../standards/frontend-design.md) 定义。

统一产品壳按用户任务组织，不按底层技术名组织：

| 一级入口 | 当前目标 | 后续扩展位 |
|---|---|---|
| 工作台 | 我的待办、快捷发起、常用应用、最近数据 | 企业经营摘要、插件组件 |
| 数据 | 业务应用/数据集目录、视图、筛选、记录详情、导出 | 插件注册数据集、跨对象视图、AI 设计 |
| 流程中心 | 可发起、待我处理、我发起、已完成、抄送、实例办理 | 委托、会签、超时、异常、转交 |
| 流程设计 | 流程图、表单、数据映射、参与人权限、发布测试 | 版本冻结、插件节点、AI 联合设计 |
| 消息 / 任务 | 保留现有能力入口和导航位置 | 统一身份后迁入平台壳 |
| 应用管理 | 展示已安装与可安装应用的位置 | 安装、升级、启停、依赖和权限审查 |
| 企业与组织 | 当前企业指示、切换入口、组织入口 | 多企业授权、数据域、成员与套餐 |

当前仍为单企业部署，因此企业切换控件必须明确显示“当前部署仅一个企业”，不能伪造多企业数据。消息、任务和 AI 是平台通用能力；文件、财务等领域能力只在真实接入且启用时出现，未接通的后续能力可以说明“待接入”，但不用空按钮冒充完成。

## 5. 数据与流程的去抽象化原则

### 数据页

- 默认先看到“已启用业务应用和数据集”；启用财务时可以显示“费用管理 / 费用报销单”，但不显示 `invoice`、`ledger` 等内部 ID。
- 进入数据集后显示业务说明、关联流程、负责人、记录状态、常用筛选和主动作。
- 字段 ID、schema、revision 等只进入高级设置；普通用户看中文字段与业务动作。
- 空状态必须告诉用户下一步：新建记录、发起流程、调整筛选或安装应用。
- AI 修改必须说明修改对象、字段/视图/动作范围，生成提案后再确认。

### 流程设计与运行

- 模板首先说明“谁在什么情况下办什么事”，并用业务路径展示：员工提交 → 经理审批 → 财务复核 → 完成/退回。
- 设计器是管理员工具；员工从流程中心发起和办理，不进入画布。
- 表单、节点参与人、数据去向、测试结果必须与同一 Workflow/DocType 元数据一致。
- 发布前至少能创建测试实例，并由真实角色完成通过和退回重提链路。

## 6. 当前实现与迁移边界

已经具备：Frappe App 安装单元、DocType/Meta、Role/Permission、版本化流程定义与运行时、Action/Tool schema、确认与审计、内置可信领域注册、统一启停和贡献聚合。`shangshu_finance` 已作为首个契约消费者声明导航、工作台、数据集、流程、动作、工具、角色和页面；公共 BFF/前端只消费聚合结果，纯内核模式已经通过本地验收。

工作台贡献的当前权威协议为 [`2026-09-02-工作台组件与布局扩展协议-v1.md`](../standards/workbench-extension-v1.md)。v1 只支持插件默认 `metric` 卡片和权限感知 provider；企业布局覆盖、拖放和完整卸载生命周期尚未实现，不得由行业分支修改公共前端补丁式实现。

尚未具备完整插件平台：任意第三方 manifest loader、依赖/冲突解析、在线安装升级卸载、签名、SBOM、隔离执行和真正 tenant scope。通用 AI 对话到 Frappe ToolDef/ActionDef 的执行桥也尚未完成；当前平台模式会禁止旧 Node StateStore 工具回退，以避免双事实。后续用财务与知识产权两个真实域验证公开 API 后，才能进入 P3 插件平台。

## 7. 第一阶段验收

1. 纯内核模式包含工作台、数据、流程中心、流程设计、消息、任务、AI、企业与内置应用管理；没有业务域时显示可行动的空状态，不显示财务名称、角色、数据集、流程或工具。
2. 启用财务后，数据页能用中文业务语义查询真实费用数据，支持筛选、导出、进入相关流程；停用后普通入口消失、数据保留且不可新建。
3. 费用报销模板能完成票据识别/核对、发起 → 经理审批 → 财务审批 → 过账 → 付款，以及退回 → 补充 → 重提；该链证明财务域与内核集成，不定义纯内核默认内容。
4. 普通员工无法读取他人记录或设计器上下文；管理员可查看发布测试与元数据。
5. 新插件协议进入文档和后续工程读序；重复注册、跨插件写数据和任意 AI 代码调用被列为禁止项。
6. 对旧 Node 工作台的数据、消息、任务和 AI 能力形成“已还原 / 保留入口 / 待迁移”的真实对照，不作虚假完成声明。
7. 财务启停经过管理员确认并写审计；停用不删除 App、DocType、历史记录或运行实例，重新启用后原配置和数据可恢复使用。
