# v0.1 设计规范与状态快照

> **文档状态：CURRENT（已确认视觉基线）**
>
> **当前工作台视觉基准，2026-08-17 定稿。**
> 以用户确认的 v0.1 实际显示为准；实现真相源是 `shangshu-web/css/deepseek.css` 的 `:root` 与组件规则。
> `workbench.css` 等文件提供结构骨架，不得重新定义另一套视觉语言。

## 1. 设计目标

精致、耐看、简约且不易视觉疲劳。信息层级依靠中性画布、白色工作卡片、留白和极少量发丝线建立；绿色只表达操作、选中和状态，不承担大面积背景。圆角只用于识别控件与面板边界，不做胶囊化装饰。

## 2. 页面结构

| 区域 | 规范 |
|---|---|
| 外层画布 | 中性灰 `#E8EAEB`，无绿味 |
| 侧栏 | 展开基准 196px、最小 176px、可拖至 420px；折叠为 56px rail |
| 工作区 | 业务主卡片 + 可选 AI 卡片；上圆角 10px，下缘直落视口底部 |
| 卡片分区 | 画布缝隙 + 发丝环 + 柔和边缘阴影，不堆叠等权框线 |
| 顶栏 | 无全局顶栏；页面标题属于业务卡片内部 |
| 移动端 | 响应式规则统一见 [前端规范第 4 节](./frontend-design.md#4-响应式与可访问性)，本页不再另定义断点 |

## 3. 唯一设计令牌

```css
/* 中性底色 */
--bg:#ffffff;
--bg-alt:rgba(0,0,0,.04);
--card:#ffffff;
--control-bg:var(--card); /* 可编辑文本控件及搜索框 */
--control-muted-bg:var(--bg-alt); /* 禁用/只读表单控件 */
--canvas:#E8EAEB;
--side-bg:var(--canvas);

/* 文字与线 */
--fg:#1e232c;
--fg2:rgba(0,0,0,.65);
--fg3:rgba(0,0,0,.45);
--line:rgba(0,0,0,.08);
--line2:rgba(0,0,0,.14);

/* 品牌与语义 */
--green:#10B981;
--green2:#0EA372;
--green-ink:#0A6E4C;
--acc:#34D399;
--accd:#E9F8F1;
--blue:#2563EB;
--blued:#E8F0FB;
--amber:#C77A0A;
--amberd:#FBF3E4;
--red:#DC4444;
--redd:#FBEAEA;

/* 圆角 */
--r:6px;       /* 面与常规按钮 */
--r-sm:5px;    /* 控件 */
--r-xs:4px;    /* tag/chip */
--r-lg:8px;    /* 浮层内部 */
--workspace-radius:10px; /* 两张主卡片顶部 */
```

禁用旧值：墨绿 `#1B3A2D / #2E5E4E / #1E4434`、暖米色 `#FAFAF7 / #F4F3EF / #F1F0EA / #EFEEE8`、主操作渐变。

2026-09-10 用户确认：侧栏与最底层画布统一灰色，`--side-bg` 引用 `--canvas`，不再保留独立浅灰色差；白色内容区不变。

## 4. 字体与品牌

- 正文与导航：`-apple-system → BlinkMacSystemFont → Segoe UI → Roboto → PingFang SC → Hiragino Sans GB → Microsoft YaHei → TaipeiSans`。
- 代码与等宽数字：`ui-monospace → SF Mono → Menlo → Consolas`。
- `brand.png`：印章 + 尚书 + Lingeringtek，仅登录页使用完整锁定组合。
- `brand-mark.png`：印章 + 尚书，工作台展开侧栏使用。
- `brand-seal.png`：仅印章，折叠 rail 静止态使用。
- 品牌统一为红印章 `#E53935` + 深灰字 `#1e232c`，绿色不进入品牌门脸。
- 三版资源由 `shangshu-server/scripts/gen_brand.py` 生成，按墨迹包围盒光学居中。

## 5. 侧栏规范

- 品牌、导航图标、分组标题、底部头像左边缘统一在 x=14px。
- 品牌带固定高 44px；展开和折叠时按钮中心高度不变。
- 导航行高 32px（22px line-height + 上下 5px），组内间距 2px，组间距 20px。
- 选中项：白色紧实指示块 + 绿色文字/图标；不使用绿底、渐变、模糊或循环扫光。
- hover：淡白预览块，不改变字号、不位移、不变绿。
- 折叠态：静止显示红印章；hover / `:focus-visible` 换成展开箭头。
- 底部账号整行打开账号菜单；登出只是菜单内的红色 danger 项，不允许整行直接登出。
- 折叠图标栏点击头像也须直接打开同一账号菜单，不先强制展开侧栏；菜单独立于侧栏裁切区域，位置和宽度受视口约束。
- 账号菜单按角色显示可访问模块；点外部或 Esc 关闭。

## 6. 组件规范

运行异常提示必须使用错误语义（`--red`、非成功图标、`role="alert"`），不得复用绿色成功提示；提示内容按纯文本展示。

| 组件 | 规范 |
|---|---|
| 常规卡片 | 白底、6px 圆角、发丝环，不叠加厚边框 |
| 主工作卡片 | 白底、顶部 10px 圆角、底部 0、柔和边缘阴影 |
| 主按钮 | `--green` 纯色白字、6px 圆角；hover `--green2`；无渐变/发光 |
| ghost 按钮 | 透明底 + 低对比发丝线；hover 中性灰 |
| 输入框/下拉框/多行文本 | 可编辑态统一 `--control-bg` 白底、5px 圆角；聚焦深灰发丝环，不通过灰变白表示可编辑；禁用/只读表单用 `--control-muted-bg`，错误保留错误边线 |
| tag/chip | 4px 圆角；默认中性灰；语义状态才使用蓝/琥珀/红/浅绿 |
| 表格 | 表头灰字；文本左、数字 `.r` 右、状态 `.c` 中；分隔线不高于 `.05` alpha |
| KPI | 白卡片；右上 26px 浅绿语义图标，不整卡上绿 |
| 悬浮层 | 白底、6–8px 圆角、`--pop` 阴影 |
| 开关 | 轨道可胶囊化（属于物理控件形态），其他按钮禁止 999px |

2026-09-29 用户确认：取消可编辑输入框的灰底。公共表单和模块内控件引用同一控件背景令牌，搜索图标容器与输入本体作为一个白底控件；不能只修邮箱设置。只读详情文字可保持透明展示；复选框、开关、画布、侧栏、表头、选中行和状态提示不属于此次白底化范围。不得修改 `--bg-alt` 把所有灰色界面一起变白。

## 7. AI 对话规范

- 同一会话支持 hidden / float / split / full，切换形态不重开会话。
- 悬浮、分栏、全屏三态背景统一为白色。
- 用户消息：右侧浅灰气泡，无绿底、无渐变、无阴影。
- AI 消息：左侧纯文字流 + 三条浅绿声波标识。
- 输入区：白底 + 发丝环 + 极浅绿光晕；无 blur 液态玻璃和内高光。
- 工具执行记录默认折叠；确认卡独立可见，白底、细边线、小圆角，待确认只用小状态点，不铺整块琥珀底。文件名/版本与动作分层，结构化字段或单元格修改用 before/after Diff（原值灰、新值浅绿），技术信息折叠。保存状态必须来自真实读回，不以颜色代替执行回执。
- AI 与业务双向联动：业务对象成为 `ui_context`；`ui_navigate` 可切业务模块；`ui_patch` 只生成草稿，应用仍需人工确认。

## 8. 动效规范

- 只使用位置、透明度、尺寸和必要的状态过渡。
- 常规 hover/开合 120–300ms，使用 `--ease`；弹层可用 `--spring`。
- 禁止常驻扫光、装饰性渐变动画、hover 字号变化和无意义位移。
- 允许：状态点呼吸、AI 声波、执行进度；必须表达真实运行状态。

## 9. 绿色使用纪律

允许：
- 主操作按钮；
- 选中项文字/图标；
- AI 状态标识；
- 开关开启态；
- 正向语义与 Diff 新值；
- 图表中的主数据序列。

禁止：
- 大面积页面/侧栏/抽屉底色；
- 用户消息气泡；
- 普通 hover；
- 非语义 tag；
- 大块 insight 背景；
- 墨绿渐变按钮或阴影。

## 10. 已否决方案

1. 墨绿主色、大面积绿底、主按钮渐变。
2. 过多等权框线或完全无结构线；保留必要发丝线。
3. 16px 大圆角、到处胶囊、圆角层层嵌套。
4. 液态玻璃 blur、内高光、循环扫光。
5. hover 变字号、图标放大、横向位移。
6. 顶部常驻 AI 输入框。
7. 把微信式会话摘要列直接照搬为全局信息架构。
8. 把账号整行做成登出按钮。

## 11. 维护规则

1. `deepseek.css :root` 是唯一令牌定义；基础 CSS 只引用变量，fallback 必须与当前令牌一致。
2. 新组件禁止写品牌色和中性底色 hex；语义色例外但优先引用令牌。
3. `deepseek.css` 继续最后加载，负责最终组件规范；基础层不得依赖“反向覆盖”维持旧视觉。
4. 设计调整必须同步本文和当天 worklog。
5. 原型文件仅供历史参考，不是生产规范。

## 12. 使用端布局收敛（2026-09-02）

- 2026-09-15 B 管理配置切片：生效字段与权限使用默认折叠的紧凑表格，复用既有表头、边线和字号；窄屏内部滚动保留全部列。不改变品牌令牌、全局导航或员工列表编辑方式。

- 2026-09-11 最新验收：应用直达数据工作面，不再设置数据入口目录中转。数据采用表格外观的列表，行末编辑打开通用弹窗；单元格编辑暂缓，未来显式启用且不改变表格外观。切表去掉绿色侧边条，窄屏沿用下划线页签，筛选控件等高。

- 2026-09-11 最新：具体应用移入全局侧栏“应用”下，内容区删除第二列应用索引；展开/折叠保持 34px 行高，折叠仍可直接打开，保留总览入口。此规则替代此前应用中间选择列。

- 2026-09-11：重复记录用表格、数据表与应用切换用紧凑列表；大卡片不作为多条数据默认布局。应用业务入口使用表格；数据目录约 180px，单项约 34px，窄工作面转横向页签，正文区域优先给数据表。应用范围与刷新保持规则见前端规范。

- 保留尚书灰白工作面、红印章和绿色主行动色，不重做产品壳。
- 借鉴成熟协作产品的交互骨架：稳定全局导航、选择列表、当前工作面。借鉴的是层级与动线，不是蓝色视觉或品牌组件。
- 工作台只回答“我现在要做什么”，优先显示待我处理、我发起、我的任务、常用应用和最近事项；平台内核状态不得作为普通用户首页内容。
- 应用页在同一页面完成应用切换与当前应用操作，不再从应用卡跳到另一张结构重复的整页。
- “流程中心”在普通用户导航中命名为“待办”；流程设计和应用管理收进管理员账号菜单，员工账号菜单不出现系统管理模块。
- 四个普通用户一级入口必须使用互不重复的语义图标：工作台=首页、消息=对话、待办=收件箱/待处理、应用=应用集合。协作任务归入待办内，不再单列；不得复用同一个四宫格或用流程编排节点代表日常待办。
- 页面说明只补足必要上下文，不用长篇引导掩盖不直觉的操作路径。
- 待办标题、类型切换与主操作共用一条紧凑工具栏；事项分类横排，不叠放独立按钮行、内侧栏和重复标题。窄屏允许工具栏自然换行，保留原品牌与全局导航。
