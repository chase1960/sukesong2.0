## 0. 怎么用这份规范

| 你要做的 | 怎么做 |
| --- | --- |
| 记一条操作痕迹 | 调 `shangshu_core.unified_log.write_log(...)` —— **全平台只有这一个写入口** |
| 加一个**域专属**字段 | 在**该域自己的扩展表**里加列（`declare_extension_fields`）—— 不许新开日志表 |
| 想查日志 | 走既有读口（`query_action_audits`／`query_business_audits`／`get_action_receipt`／`record_history`）—— 形状不变 |

## 1. 什么算日志

**日志＝「谁在什么时候动了什么」的痕迹。**

统一日志表（`Shangshu Unified Log`）的每一行都有这九个通用字段：

| 字段 | 装什么 | 为什么这么装 |
| --- | --- | --- |
| `log_no` | 日志编号（`LOG-2026-00001`） | 唯一、能点回原始记录 |
| `occurred_at` | 发生时间 | 「什么时候」 |
| `actor_user` / `actor_identity` | 谁（人＋执行身份） | 「谁」 |
| `trigger_source` | 怎么触发的：人点的／助手选的／定时跑的／系统跑的／不知道 | 人工动作与后台动作不能混同 |
| `domain_id` | 属于哪个域 | 域被拔掉时能定位它自己的东西 |
| `what_kind` | 做了什么（类别）：动作／事件／工具／域启停／过程 | 四类痕迹合成同一种行，靠它区分 |
| `what_id` | 做了什么（标识）：动作 id／事件 id／工具 id／启停 | 指向具体那件事 |
| `result` | 结果：成功／失败／投递中／被拒／未知 | 「成没成」 |
| `business_object_id` / `business_name` | 跟哪条受管记录有关 | 日志要能**按案件看**；只记编号，不抄值 |
| `detail_json` | 详情 | 输入摘要、**改了哪些字段的前后值**、结果摘要、为什么选了这个工具 |

> **技术列**（不属于九个通用字段，但每行都有）：`reference_doctype`／`reference_name`（被改动的记录）、`idempotency_key`（幂等键）、`source_doctype`／`source_name`（来源指针，能点回原始记录）。

## 2. 日志库承载什么

1. **四类平台操作痕迹**（都变成同一种行）：
   - **动作执行审计**：谁执行了哪个动作、成没成、输入与结果摘要、改了哪些字段的前后值。
   - **事件信封**：事件发了、谁收到没收到、投递结果与失败原因。
   - **AI 执行审计**：用了哪个工具、为什么选它、候选有哪些、模型与工具版本。
   - **域变更审计**：域启停与变更 —— 谁改的、为什么、改前改后。
2. **各域自己的过程记录**（进同一张表；域专属字段走扩展字段）：
   - example：官文到没到／谁审核的／自动化判断了什么／**官方状态的对齐过程**（对齐结果不在日志里，在受管列里）。
   - Host：运行日志／包台账／导入批次与导入件／入站通知书／同步作业。

---

## 3. 日志库**不**承载什么（边界，写死）

> **界线**：日志记「**这次操作涉及了什么值**」（输入、变更前后值、结果摘要），**不记「那条记录的当前值」**。

| 规则 | 为什么 |
| --- | --- |
| 日志记「这次操作涉及了什么值」 | 这是操作的证据 |
| 日志**不**记「那条记录的当前值」 | 当前值住在受管记录里（那是唯一事实）；抄进日志就是**第二份存储** |
| 但**变更前后值要留** | 「有人改过」没有前后值等于没说 |
| 业务值可以进日志 | 用户 2026-10-22 11:40 放宽：**不做业务值过滤/脱敏**（这里是操作里出现过的值，不是记录的当前值） |
| **对齐结果不进日志** | 官方状态对齐的结果住在受管列里；日志只记对齐的过程与人工审核情况 |

**受管记录才是业务当前状态的唯一事实。** 同一个值只存一处。

---

## 4. 域专属字段：分表存（可解耦）

- **每个域一张扩展表**（不是「一张大表加一堆可空列」—— 后者正是「域被拔掉后字段还在」的病根）。
- **扩展表的每一行必须带主行的 `log_no`**（外键级）⇒ 读口按 `log_no` 把域字段接到主行上。
- **域被拔掉（退役/停用）⇒ 它的扩展字段随之消失**（那张扩展表连同字段一起删）；主日志表与别域不受影响。
- **分表存 ≠ 另开日志库**：主日志表**只有一张**、写入**只有一处**。分表只是「字段放哪」的问题。
  ⇒ **以后加字段＝加在该域的扩展表里，不许新开日志表。**

机器检查器 `npm run check:logs`：
- 判「什么算日志表」的判据**从内核契约取**（`common_fields.required` 的字段清单 ＋ `exempt_tables.tables` 的豁免名单）—— 检查器里不另写一套。
- 扫各域的受管对象定义，发现「日志性质的表」且不在豁免登记里就报出来（退出码 1）。

## 5. 旧表怎么办

四张旧表（`Shangshu Action Execution Audit`／`Shangshu Event Envelope`／`Shangshu AI Execution Audit`／`Shangshu Domain Change Audit`）：

- **保留表结构与历史行**（历史行还要查得到）；
- **不再新增**（新痕迹只写统一表；**不许双写** —— 同一个值不许同时落旧表和统一表）；
- 读口把旧表历史行与统一表新行**合并**返回，**既有返回形状不变**。

> **例外（已知取舍）**：`Shangshu Event Envelope` 仍是**活队列**（投递重试要靠它，example 的业务判断结论也住在它里面）⇒ 它继续存在。
> 统一日志里存的是**事件痕迹**（发了什么、给了谁、成没成、失败原因），**不抄**载荷与业务判断值。

---

## 6. 硬纪律

1. **不许另开日志库**：以后任何用例都用这个日志库（机器检查器盯着）。
2. **按域加字段要解耦**：域被拔掉 ⇒ 它的字段随之拔掉。
3. **写下就锁住**：日志不可改、不可删（纠错要追加新行）。
4. **统一日志是唯一的新写入处**：写日志只调 `shangshu_core.unified_log.write_log(...)`。
