# 尚书平台前端设计规范（2026-08-31）

> **文档状态：CURRENT（现行前端与响应式标准）**
>
> 当前 Frappe 产品壳的视觉与页面实现基准。完整的应用层、页面/表单设计器、工作台配置、流程入口和首次使用路径以 [`2026-09-01-完整低代码平台产品与架构设计.md`](../architecture/low-code-platform.md) 为准；本文继续约束视觉令牌、公共页面和响应式，不再单独定义完整信息架构。

## 1. 信息架构

2026-09-22 内部工具补充：用户要求表格工作面 `#/sheets` 对齐最新 3in `2cad1c70`，故该工作面改为双击可写单元格直接编辑、修改条在表格上方、统一保存/撤销，不再要求先点“进入编辑模式”。保留失败输入及版本冲突校验；只读字段不可编。此补充仅覆盖新表格工作面，不自动改变应用内既有列表/表单。旧 9/11 显式编辑模式要求对本工作面不再生效。

- **工作台**：待我处理、我发起、我的任务、常用应用、最近事项和领域指标贡献位。
- **数据**：按已启用业务应用组织数据集；当前财务域启用时的真实数据集包括“费用报销单”，财务停用时不得显示财务数据集或内部 ID。
- **待办**：可发起、待我处理、我发起、已完成、抄送和实例办理；“流程设计”不属于普通用户入口。
- **流程设计**：流程图、表单页面、数据流转、办理权限、发布测试。
- **平台通用入口**：消息、任务、AI、应用管理和企业设置；财务、知识产权、文件等属于业务域，只在真实接入且启用时注册入口。

默认登录进入工作台。数据记录可以直接打开对应流程实例，工作台可以直接发起报销或进入指定流程视图。

2026-09-10 最新确认：任务归入统一“待办”入口，侧栏为工作台、消息、待办，分隔线后是应用。待办内分“流程事项”和“协作任务”；流程发起与任务发布保持各自表单和权限。旧任务链接/工作台快捷入口进入待办的任务视图，旧浏览器布局不再单列任务，保留其他个人偏好。此规则替代旧五入口排列。

使用端统一采用“稳定全局导航 + 选择列表 + 当前工作面”的结构：左侧全局导航不随页面变化；应用页在中间选择应用、右侧直接办理；待办页内切换流程事项与协作任务，再处理对应列表或实例。参考成熟协作产品的信息密度与操作动线，但不复制其品牌、颜色或组件外观。2026-10-10 用户确认按员工动线归类：工作台、消息、待办，以及已启用且有权限的邮箱、文件中心归入“工作”；应用归入“业务”，不再把日常文件/邮件另列“工具”。归类不改变领域启停、权限及自定义扩展，不清空个人偏好；协作任务仍在待办内。应用设计、应用管理、AI 工具、模块和系统设置只进入管理员账号菜单。

“可以直接发起报销”仅适用于财务域已启用且当前用户有权限的状态。纯内核模式的工作台不得出现财务快捷入口，而应显示我的待办、最近活动、通用协作入口和“管理/启用业务应用”的可行动空状态。

## 2. 页面原则

2026-09-29 表单统一：可编辑输入、下拉、多行文本及复合搜索框统一白底，引用视觉基线的 `--control-bg`，模块不再自行定义灰底。禁用/只读保留状态区别，错误保持语义边线；不改变灰色画布/表头或绿色主操作。普通表单复用公共规则，不为各页面新造控件组件或专用补丁。

2026-09-29 首屏加载修订：正文优先既有系统字体，不为后备中文字体做无条件大文件预载。启动状态反馈内联于外部样式之前，样式实际就绪再展示工作面；下载失败或超时须给明确重试，不以固定时长强撤遮罩掩盖裸页面。维持内容指纹缓存，不通过清空全部用户缓存解决版本问题。

2026-09-15 B 配置增量：数据表的“查看规则与权限”默认折叠，展开用紧凑表格展示生效字段/类型/约束/角色；与草稿编辑明确分开，当前账号操作不冒充员工权限模拟。窄屏保留全部列并在表内滚动，不沿用数据入口目录隐藏说明列的规则。不增加员工端管理诊断。

2026-09-11 数据管理验收修订（优先于下面旧应用主页描述）：有数据表的应用直接打开首张已授权表，保留应用名、切表、配置及已注册发起操作，不再先展示“业务记录”链接目录。无数据表的流程应用仍保留发起入口。当前统一用表格外观的列表，行末明确“编辑/查看”，编辑复用完整表单；不提供单元格内确认按钮或未完成的模式切换。后续表格编辑必须显式启用、保持同一布局，完成保存/失败/退出策略后再交付。筛选输入与按钮统一 34px；少列填满工作面，多列只在表内横向滚动。原生下拉弹层样式按用户决定暂缓。

侧栏具体应用与平台入口必须复用 `sidebarItemHtml`、`.side-item` 和同一选中指示块，不另写近似样式。具体应用打开时只有该项高亮，总览入口不同时选中；无收藏能力的入口不显示假收藏按钮。

应用切换不得重建未变化的侧栏目录；同一工作面只更新详情和选中态，重复点击当前项不重复加载。目录刷新拒绝迟到响应，不通过取消动画掩盖不必要重绘。

2026-09-11 导航收敛：具体可访问应用直接列在全局左侧“应用”入口下方；“应用”仍打开总览。内容区不再设置第二列应用索引，空间留给业务页面。折叠侧栏保留可点击的应用标记与名称提示；列表使用后端授权目录，不能硬编码业务应用或另建权限。

2026-09-11 用户验收补充：多条记录默认表格、多项导航默认紧凑列表，贴近 Excel 管理习惯，不用大卡片堆叠数据。应用内数据页只取该应用已授权的绑定（包括显式跨域引用），保留应用名、返回入口和刷新后的当前表；不能跳入全平台目录。桌面数据目录独立滚动，窄工作面横向切表，宽表在表格内部滚动。不得按测试名称硬编码隐藏资源；自动回归夹具不应混作整洁验收样例。

应用和待办标题工具栏按钮统一 34px 高、13px 字号、20px 行高、14px 水平内边距（border-box）。同一行主次按钮不得混用 btn-sm；仅用颜色和边框区分优先级，文字长度决定宽度。

应用列表与详情共用 60px 标题带，标题字号、垂直中心对齐；应用主页只显示名称及主操作，不堆领域名、宣传说明和流程路径。业务记录只出现一次；主流程留在标题带，其他流程在“发起业务”区保留。不得为视觉收敛删除真实业务资源或修改其权限。

应用入口默认展示“全部应用”并支持搜索；显式应用直达/配置预览才进入指定应用。配置切换一次只显示一个面板，返回保留应用选择。所有异步渲染同时校验页面生命周期和当前容器，离开后不得用迟到响应覆盖新页面；失败重试保留该生命周期约束。

待办使用紧凑单行页头：标题、流程/任务切换、当前视图主操作放在同一工具栏，窄屏按内容换行。流程事项分类使用横向筛选，不再占一整列内侧栏；不重复显示已选分类标题，不给单个发起按钮留整行空白。流程与协作任务的运行语义不受布局改变影响。

1. 普通用户文案使用业务名称；内部状态、DocType 和 fieldname 仅在高级说明中展示。
2. 不使用大 Hero、点阵背景和成组解释按钮；顶部只留页面目标，主操作靠近数据。
3. 流程实例必须显示业务路径和“现在该做什么”；不只显示英文状态名。
4. 设计器压缩平台侧栏，画布占据剩余空间；配置分视图，不叠在画布上。
5. 未实现功能使用“插件位/待接入”，点击后解释边界，禁止空白页或假成功。
6. 页面不得假设财务永远存在。导航、工作台卡片、数据集、流程模板、角色文案、AI 工具和快捷动作必须由领域注册结果生成；纯内核空状态也是正式产品状态，不是报错或残缺页面。
7. 不以长篇说明替代可操作结构。工作台先展示真实数量和最近事项；应用页选择后不跳转另一张整页；待办视图切换不离开当前工作面。
8. AI 页面上下文由产品壳统一提供：进入任何正式页面都上报页面级上下文；选择应用、数据记录、任务、会话、待办视图、流程实例或设计节点后升级为对象级上下文；离开页面自动切换。业务事实仍需通过当前用户有权调用的工具重查，页面上下文不能绕过权限或确认。

## 3. 视觉令牌（速查，定义以视觉基线为准）

完整令牌和品牌规则唯一维护在 [视觉基线](./visual-baseline.md)，本节只保留速查；修改时不得各自定义不同值。

本产品壳不得为 Frappe 另起视觉体系，唯一基准仍是《2026-08-15-设计状态快照》：

- 画布与侧栏统一 `#E8EAEB`（侧栏引用画布变量），内容面白色；边线 `rgba(0,0,0,.08)`，主文字 `#1e232c`。
- 主操作用 `#10B981`，选中与 hover 用 `#0EA372`，深色绿色文字用 `#0A6E4C`。
- 常规卡片和按钮圆角 6px、输入框 5px、标签 4px；只有主工作面顶部使用 10px。
- 数据表保持高密度；桌面导航 196px，设计器紧凑导航 56px。
- 展开侧栏使用红印章加“尚书”的品牌门脸；禁止临时黑底字标、绿色 Logo 或 Frappe 默认品牌替代。
- 页面标题属于白色业务工作面内部，不增加独立的全局产品顶栏。

## 4. 响应式与可访问性

- 导航、数据目录与 AI 分栏按实际可用空间降级；折叠前后导航按钮中心高度保持一致，常见桌面窗口不得因 AI 面板打开而发生不稳定中间态。
- **待专项复核的数值**：旧本文写 720/600px 图标栏与横向入口，旧视觉快照写 768px 抽屉，当前 CSS 仍含 768px 规则。两套数值不再同时作为有效要求；本次仅消除文档双重指令，不修改现有行为。下一次响应式任务须先用现有页面和浏览器验收确定单一断点策略，不能只按旧文档重写侧栏。
- 390px 必须 `scrollWidth == innerWidth`；通用业务表保留字段，宽表在自身容器滚动，不硬编码成事项+金额两列；详情仍可达。
- 图标按钮均有 `title` 或 `aria-label`；视图切换保持键盘可点击。

## 5. 插件前端接入约束

插件只能通过声明式导航、应用卡、数据集、页面和设置插槽接入。资源 ID 必须进入插件命名空间；平台拒绝重复注册和隐式覆盖。插件使用平台令牌和通用控件，不复制侧栏、登录页、确认卡或权限逻辑。

当前 `platform_shell.js` 是产品壳 PoC，不是最终插件 loader。后续需把硬编码入口改为 manifest 注册表，并补依赖、权限申请、启停和错误隔离。

## 6. 领域启停的前端状态

### 纯内核模式

- 工作台保留待办、活动、消息、任务、AI 和应用管理，不出现费用、发票、记账、应收应付或财务角色。
- 数据页展示已启用应用的数据集；没有数据集时说明“尚未启用业务应用”，提供进入应用管理的真实入口。
- 流程中心保留通用的可发起、待我处理、我发起、已完成和抄送视图；没有流程时给出启用应用或由管理员设计流程的下一步。
- 流程设计保留定义目录和编辑能力，但不自动注入费用模板。
- 不展示虚构的多企业、应用市场或尚未接通页面。

### 财务域启用

- 由财务域注册费用工作台卡片、财务数据集、费用流程、财务角色文案和受权限裁剪的 AI 工具。
- 普通用户先看到业务名称和主动作；对象 ID、字段 ID、ActionDef ID 和技术来源只在管理员高级设置中出现。

### 财务域停用

- 隐藏新建、新发起和普通导航入口；已运行实例仍可从“待我处理/我发起/已完成”进入，页面明确标注“该业务域已停用，仅允许完成存量事项”。
- 历史记录只能通过有权限的历史/审计路径读取，不从日常数据目录继续招揽新操作。
- 管理员重新启用后恢复原有入口和数据，不创建重复模板或重复资源。

### C 待办与领域预检

- 待办默认“全部待办”，以原表格风格显示事项、来源、当前步骤、办理；流程事项/协作任务保留原工作面，不新造第二套办理表单。业务事项回到应用数据集中的记录详情及受管 Action。
- 聚合源失败明确显示，不伪装无待办；来源服务每次最多 100 项，完整列表在原应用。页面切换后的迟到响应不得覆盖新页面。
- 管理后台原领域卡片内折叠紧凑依赖/引用/运行表，展示要求版本及实际版本。核心始终受保护；启停预检缺失或失败不能显示可安全停用，提交仍由后端复查。没有新增全局视觉主题或独立诊断平台。
