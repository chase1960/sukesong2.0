# HR 中台蓝图：从员工数据资产到数字分身

版本：2026-11-18 · 对应代码：`shangshu-server/src/capabilities/hr/`、`shangshu-web/js/domains/hr/`

## 0. 一句话结论

传统 HR 系统沉淀的是**流程记录**（谁在什么时候走了哪个审批）；这个中台沉淀的是**员工事实**（他做过什么、证据是什么、谁核实过、能不能被引用）。事实层之上才有能力差距、培养、经验复用、数字分身和招聘单位经济。没有事实层，后面的东西全是印象派。

## 1. 对标基线：别人有什么

| 能力块 | 北森 iTalent | Workday HCM | Phenom | 我们当前 |
|---|---|---|---|---|
| 组织人事（编制/档案/异动） | 核心 | Core HR | 弱 | 编制 + 员工档案（演示级） |
| 招聘（岗位→Offer→入职） | 核心 | Recruiting | 强（talent experience） | 已有完整流水线（复用招聘域） |
| 绩效与人才盘点 | 核心 | Talent & Performance | 中 | 事实 + 覆盖度评分（未做九宫格） |
| 技能图谱 / 内部人才市场 | 有（盘点） | Skills Cloud | 核心（talent marketplace） | 岗位能力模型 + 差距 + 内部可转岗匹配 |
| 培训与学习 | 外围 | Learning | 中 | 90 天计划 + 柯氏四级 + ROI |
| 数字员工 / Agent 治理 | 无 | **Agent System of Record**（2025 起） | 无 | 数字分身 + 人机分级 L0–L4 |
| 经验/知识沉淀 | 弱（文档库） | 弱 | 弱 | SRO 知识卡 + 版本 + 复用采纳率 |
| 招聘成本工程 | 报表 | 报表 | 渠道分析 | 单位经济 + 建议 + 预算调整 + 回测 |

对标结论：
1. **别人有的我们必须有**：编制与档案、招聘全链、绩效盘点、技能图谱、学习、权限审计。缺哪块，客户第一轮就把我们当"不全"。
2. **别人没有的三块，是我们的差异点**：① 员工事实的可核实证据链（不是自评表）；② 员工授权的数字分身（不是企业侧"AI 替员工说话"）；③ 招聘降本的**回测闭环**（不是"给你一张更漂亮的大屏"）。
3. **不自欺**：Workday 把 Agent 当"员工"登记、授权、审计，我们做的是同一件事的轻量版——分身有授权人、有期限、有边界、有问答审计；没有这些就不叫分身，叫泄露。

## 2. 数据资产模型：七层，缺一层就失真

```
L0 组织      hr_org_units          部门 / 编制 / 在岗          → 缺口与编制使用率
L1 主体      hr_employees          工号 / 岗位 / 司龄 / 上级   → 谁能被盘点、谁向谁汇报
L2 事实      hr_employee_facts     项目 / 绩效 / 培训 / 反馈 / 获奖 / 技能证明 / 知识
L3 能力      hr_skill_models + 员工 skills 标签               → 岗位要求 vs 个人现状
L4 计划      hr_learning_plans + hr_learning_events           → 差距怎么补、补了有没有用
L5 知识      hr_knowledge + versions + usages                 → 经验能不能被别人复用
L6 边界      hr_twins + hr_autonomy_policies/decisions        → 哪些数据可对外、哪些动作必须人做
```

事实层的四条硬规矩：
- **一条事实一个来源**：`kind + title + summary（情境/行动/结果）+ occurred_at + evidence_strength(1–3)`。
- **谁确认谁背书**：走 `hr.fact.record` 确认卡，落库即 `verified`，`verified_by` 记人。
- **会过期**：超过 18 个月标 `stale`，过期证据不允许支撑分身回答与晋升结论。
- **不许合并计算**：同一事实不能在两个维度重复计分（盘点规则也写进了知识卡）。

覆盖度评分（`assets.ts`，100 分 7 项）：基本信息 15 / 教育 5 / 能力 20 / 事实 25 / 项目绩效 15 / 学习 10 / 知识 10，A≥80、B≥65、C≥50、D<50。覆盖度不是 KPI，是"这份画像能不能用来做判断"的准入线：<60 分的人不进分身、不进内部人才市场推荐。

## 3. 数字分身：员工授权，不是企业代言

设计取舍（`twin.ts` 头注释已写明）：
- **数据来源限定**：只用已核实事实、已发布知识、能力标签。不读私聊、不读邮件正文、不读绩效原始评语。
- **授权是 L4**：`hr.twin.authorize` 由本人/HR 负责人确认，写清可见主题、拒答主题、期限（默认 180 天）、数据策略（`salary=false / performance=summary_only / others_evaluation=false / personal=false`）。
- **敏感即拒答**：薪酬奖金、绩效评级细节、他人评价、离职求职、健康婚育、法律医疗、公司未公开信息，命中直接拒答并给"去找本人/走正式流程"的出口。
- **答不了就转人**：检索不到证据时返回 `insufficient`，不编。
- **每条回答带引用**：fact id / knowledge id / skill 名，可回溯到证据。
- **就绪度 4 检查**：授权有效 / 覆盖度 ≥60 / 已核实事实 ≥3 / 边界已声明；不满足不允许上线。

运营指标（`twinMetrics`）：可用率（answered/queries）、拒答次数与主题分布、答不了的问题清单（这份清单就是下一批要补的数据）、平均引用数、节省工时估算。**拒答率不是越低越好**：拒答集中在薪酬绩效，说明边界在起作用；拒答集中在岗位职责，说明范围声明有问题。

## 4. HR 核心流程的 AI Native 重构

判断标准：不是"给旧流程加个 AI 按钮"，而是**把流程里的判断点重新分配给人或 AI，并让 AI 的产出必须可核实**。

### 4.1 招聘：从"筛简历"到"单位经济"

现状（招聘域已实现）：岗位 → AI 生成 JD（人改）→ 收简历 → AI 解析 → AI 筛选建议（人定夺）→ 面试 → 评价 → Offer → 审批 → 入职。
AI Native 增量（本域）：
- 招聘结果回流成**渠道单位经济**：`CPA、各阶段转化、90 天质量率、cost_per_quality_hire`。
- 规则化建议四类：高 CPA 渠道迁预算 / 高质量渠道加投 / AI 预筛覆盖不足 / 内部可转岗优先。
- 人确认后**真的改预算**（`hr.recruit.budget.shift`），一个周期后**同口径回测**，结论只写"达标/未达标/暂无变化"。
- 衡量的不是"用了多少 AI"，而是"每个合格入职的人，企业少花了多少钱、少用了多少天"。

### 4.2 培养：从"课时统计"到"差距—动作—行为—结果"

- 输入是岗位能力模型与个人技能差距（`priority = gap × weight`），不是"全员必修 8 门课"。
- 计划强制三阶段（0–30 / 31–60 / 61–90 天），动作必须落到 course / mentor / project / reading / knowledge 之一，且**必须产出一张知识卡**——培训不产出可复用知识，等于没发生。
- 效果用柯氏四级 + 行为转化率 + 能力 uplift + ROI 文案；学时只是成本项，不是成果。

### 4.3 经验沉淀：从"写复盘"到"可被检索、被复用、被验证"

- 采集：同一标签下 ≥2 条已核实事实，才允许生成知识草稿（单条故事不是经验）。
- 结构：SRO（情境 / 行动 / 结果）+ 可复用规则 + 标签 + 来源员工与事实 id。
- 发布：生成新版本，旧版本永久保留（`hr_knowledge_versions`）。
- 复用：每次引用记 context + 是否采纳；采纳率是知识质量的唯一硬指标。
- 淘汰：90 天零引用、采纳率持续偏低 → 建议 archive / revise，仍由人确认。

## 5. 新模块：人才资产驾驶舱 + 招聘单位经济（可视化与降本）

`GET /api/hr/overview` 单接口聚合，页面第一屏只放六个数：
在职人数（含编制缺口）、员工数据资产覆盖度、单人招聘成本（AI 抵扣后）、AI 独立处理次数、数字分身可用率、知识采纳率。

第二屏四块：
1. **部门资产热力**：部门 × 覆盖度 × 事实密度 × D 级人数 —— 回答"哪个团队的数据不能用来做决策"。
2. **企业能力缺口**：按缺口人数排序，直接对应培养预算该投哪。
3. **招聘漏斗与单位经济**：触达→初筛→面试→Offer→入职，加 4 个成本数（总投入 / 单人成本 / AI 抵扣后 / AI 节省），并标注"同企业内相对比较"。
4. **风险与待处理**：只列会改变结论的问题（画像薄、证据过期、质量率低、分身拒答集中）。

"用更少的成本招更好的人"在这个模块里的定义是可计算的：
```
单人成本 = (渠道外部支出 + 内部工时 × 220 元/小时) / 入职人数
AI 抵扣后 = (总投入 - AI 预筛节省) / 入职人数        # 25 分钟/份 × 次数 × 220 元/小时
质量率   = 90 天通过试用期或首评达标人数 / 入职人数
每质量入职成本 = 渠道支出 / 质量入职人数
```
衡量效果的闭环：建议 → 人采纳改预算（记 baseline）→ 下一周期回测 → `measured` 写入 before/after/delta/verdict。**没有回测的建议不允许标"已完成"**。

## 6. 什么时候要人介入：L0–L4 + 硬护栏

| 级别 | 名称 | HR 语境 |
|---|---|---|
| L0 | 观察 | 只读、只提示（如"这条证据已过期"） |
| L1 | 建议 | AI 出建议，人可一键采纳（知识复用记账、简历解析） |
| L2 | 代人执行可逆动作 | 登记事实、记录学习行为、发布知识（可回滚/有版本） |
| L3 | 计划确认 | 90 天培养计划、渠道预算调整（承诺资源、跨周期） |
| L4 | 人主办 | Offer 审批、薪酬变更、绩效评级、离职处理、纪律处分、分身授权、分级策略 |

判定维度（`autonomy.decide`）：风险等级、可逆性、影响面（个人/团队/公司）、AI 置信度、敏感数据（薪酬/绩效/健康/法律）。硬护栏：**敏感数据 + 不可逆 + 公司级影响 → 直接锁 L4**；默认 L4 不允许下调；`hr.autonomy.set` 仅 admin，且只能抬高门槛（`canOverride`）。

落地口径：
- 页面按钮只对当前级别开放的操作出现；L4 动作必须经过确认卡，且卡片上写清"为什么是 L4"。
- 每次决策写 `hr_autonomy_decisions`，含级别、理由、actor；这是以后复盘"AI 到底替人做了什么"的唯一台账。
- 不追求"自动化率"，追求"人把时间花在只有人能做的判断上"。

## 7. 知识沉淀与自进化：只提案，不自行改事实

自进化在这个中台里的定义很窄，也很硬：
1. **从事实到知识**：同标签 ≥2 条已核实事实 → 草稿（人可改）→ 发布生成版本。
2. **从使用到健康度**：复用次数、采纳率、零引用时长 → `knowledgeHealth` 给出 promote / revise / archive 建议。
3. **从拒答到补数**：分身答不了的问题聚合成"数据缺口清单"，驱动下一轮事实采集。
4. **从决策到分级校准**：L4 占比过高说明流程设计太保守；L2 误判率高说明该升级。调整仍需人确认。

红线：AI 不改写知识正文、不改员工事实、不扩大授权范围。所谓"自进化"是**证据与规则的版本迭代**，不是模型偷偷改结论。

## 8. 度量体系

北极星：**可用于决策的员工数据覆盖率**（覆盖度 ≥60 且事实 ≥3 的人 / 在职人数）。
护栏指标：
- 数据质量：过期证据数、无上级人数、事实人均数、核实率。
- 招聘：单人成本、每质量入职成本、Time to Hire（待接）、渠道质量率、内部填补率。
- 培养：计划完成率、行为转化率、能力 uplift 数、每 uplift 成本。
- 知识：发布数、复用次数、采纳率、零引用条目数。
- 分身：可用率、拒答率与主题、答不了清单长度、平均引用数。
- 人机：L0–L4 分布、L4 占比、待确认挂起时长、决策台账完整率。
- 体验：HR 每完成一次"事实登记/计划发布/建议采纳"的点击数与耗时。

## 9. 90 天落地路线

| 阶段 | 目标 | 关键动作 |
|---|---|---|
| 0–30 天 | 事实层可用 | 选 2 个部门做事实采集；补岗位能力模型；覆盖度从 61 → 75；开通 3 个分身试点 |
| 31–60 天 | 流程闭环 | 培养计划跑完一轮（柯氏 L3 有数据）；知识发布 ≥10 条并开始被复用；招聘渠道单位经济接真实数据 |
| 61–90 天 | 降本验证 | 采纳 2 条招聘建议并回测；内部转岗填补 ≥1 个岗位；形成"哪些动作必须人做"的部门共识并写进策略 |

## 10. 不做什么（同样重要）

- 不做员工监控（不采集聊天、位置、屏幕、健康数据）。
- 不做"AI 自动给绩效打分"——评级是 L4。
- 不做无证据的九宫格与人才盘点结论。
- 不做炫技大屏：每个可视化必须对应一个可执行动作或一个可回测指标。
- 不把"AI 生成"当作质量背书：所有 AI 产出都必须有人确认或证据引用。
